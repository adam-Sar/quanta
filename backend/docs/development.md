## Engineering standards

- Python 3.12 typing and Pydantic v2 at external boundaries.
- Small routes delegate to services; services use repositories/interfaces; processing and provider adapters remain replaceable.
- SQLAlchemy entities are internal. Alembic revisions are reviewed, not blindly autogenerated.
- Original files and dataset versions are immutable; write workflows require cleanup and idempotency planning.
- Statistical methods document assumptions, minimum sample sizes, sampling, algorithm versions, complexity, and failure modes.
- AI consumes bounded structured findings, returns validated structures, and never executes arbitrary code.
- No logs contain files, rows, credentials, tokens, request bodies, or provider prompts with sensitive evidence.
- Tests assert business outcomes and negative cases. Real PostgreSQL tests use disposable infrastructure.

## Migration workflow

After Task 4 model imports are wired to `Base.metadata`:

```bash
alembic revision --autogenerate -m "create findings tables"
alembic upgrade head
alembic downgrade -1
alembic upgrade head
```

Review types, indexes, constraints, server defaults, locks, and data migration safety. Production downgrades that would destroy data may deliberately fail with a documented forward-fix strategy.

## Dependency policy

Add dependencies in the task that uses them. Keep versions bounded, update the lock/deployment strategy before production, and avoid overlapping libraries without a documented role. Polars is the default frame engine; DuckDB handles analytical SQL and file/multi-dataset scans; PyArrow is interchange/Parquet; Pandas appears only for compatibility.
